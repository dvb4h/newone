# منصة التعرفة الجمركية الذكية — نظام تسجيل دخول واشتراكات

مشروع Flask + SQLite يضيف نظام تسجيل دخول، لوحة تحكم للأدمن لإدارة المشتركين
(مع تحديد مدة الاشتراك)، ولوحة للمشترك تعرض حاسبة التعرفة الأصلية مع بانر
يوضّح عدد الأيام المتبقية من الاشتراك.

## هيكل المشروع

```
tariff_app/
├── app.py                      # السيرفر الرئيسي (المسارات، تسجيل الدخول، منطق الاشتراكات)
├── requirements.txt            # المكتبات المطلوبة
├── database.db                 # يُنشأ تلقائياً عند أول تشغيل (لا تنشئه يدوياً)
├── templates/
│   ├── login.html              # صفحة تسجيل الدخول
│   ├── admin_dashboard.html    # لوحة تحكم الأدمن (إضافة/حذف/إيقاف مشتركين)
│   └── user_dashboard.html     # واجهة حاسبة التعرفة الأصلية + بانر الاشتراك
└── static/                     # لو احتجت وضع ملفات pricing.json / pricing2.json هنا لاحقاً
```

## 1. التشغيل محلياً

### أ. تجهيز البيئة

```bash
cd tariff_app
python3 -m venv venv
source venv/bin/activate        # على ويندوز: venv\Scripts\activate
pip install -r requirements.txt
```

### ب. تشغيل السيرفر

```bash
python app.py
```

سيقوم السيرفر تلقائياً بـ:
- إنشاء ملف `database.db` وجدول `users` عند أول تشغيل.
- إنشاء حساب أدمن افتراضي:
  - **اسم المستخدم:** `admin`
  - **كلمة المرور:** `admin123`

افتح المتصفح على: `http://127.0.0.1:5000`

> ⚠️ **مهم:** غيّر كلمة مرور الأدمن فوراً بعد أول دخول (لا توجد حالياً صفحة
> "تغيير كلمة المرور" فهذا يتطلب حذف المستخدم القديم وإضافة أدمن آخر يدوياً
> عبر sqlite3، أو يمكنني إضافة هذه الميزة لاحقاً إذا احتجتها).

### ج. كيف يعمل نظام الاشتراك

- عند إضافة مشترك من لوحة الأدمن، تحدّد **مدة الاشتراك بالأيام** (مثلاً 30 يوم).
- يُسجَّل `start_date` تلقائياً بتاريخ الإضافة.
- الأيام المتبقية = `(start_date + duration_days) - تاريخ اليوم`.
- إذا انتهت المدة (الأيام المتبقية أقل من 0) أو تم إيقاف الحساب من الأدمن، لا يستطيع المستخدم تسجيل الدخول، وتظهر له رسالة توضيحية.
- في لوحة الأدمن يمكنك: إضافة مشترك، إيقاف/تفعيل الحساب، أو حذفه نهائياً.

## 2. رفع المشروع على استضافة

المشروع Flask عادي، يعمل على أي استضافة تدعم Python. أشهر الخيارات:

### الخيار الأول: Render.com (مجاني/سهل)

1. ارفع المشروع إلى مستودع GitHub.
2. من Render: **New → Web Service** واختر المستودع.
3. إعدادات البناء:
   - **Build Command:** `pip install -r requirements.txt`
   - **Start Command:** `gunicorn app:app`
4. أضف متغير بيئة `SECRET_KEY` بقيمة عشوائية قوية (من Environment tab).
5. Render يوفر مساحة تخزين مؤقتة فقط للملفات — **قاعدة بيانات SQLite ستُحذف عند
   كل إعادة نشر (redeploy)** ما لم تستخدم خدمة "Persistent Disk" المدفوعة.
   إذا كنت تريد بيانات دائمة مجاناً، الأفضل الانتقال لاحقاً إلى PostgreSQL
   (يمكنني تعديل الكود ليدعم PostgreSQL إذا رغبت).

### الخيار الثاني: PythonAnywhere (يدعم SQLite بشكل دائم مجاناً)

1. ارفع ملفات المشروع عبر لوحة Files أو `git clone`.
2. من تبويب **Web**: أنشئ تطبيق Flask جديد يشير إلى `app.py`.
3. حدد مسار المشروع الصحيح في إعداد الـ WSGI file (استيراد `app` من `app.py`).
4. ثبّت المتطلبات عبر Bash console:
   ```bash
   pip install --user -r requirements.txt
   ```
5. أعد تشغيل التطبيق (Reload) من لوحة Web.
   قاعدة البيانات SQLite هنا تبقى محفوظة بشكل دائم على القرص.

### الخيار الثالث: VPS (مثل DigitalOcean / Hetzner) مع Nginx + Gunicorn

```bash
# على السيرفر
git clone <رابط المستودع>
cd tariff_app
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt

# تشغيل تجريبي
gunicorn -w 4 -b 127.0.0.1:8000 app:app
```

ثم اربطه بـ Nginx كـ reverse proxy، وأضف شهادة SSL عبر Let's Encrypt
(`certbot`)، وشغّله كخدمة دائمة عبر `systemd` أو `supervisor`.

## 3. نقاط أمان مهمة قبل النشر الفعلي

- **غيّر `SECRET_KEY`** في `app.py` (أو اضبطه كمتغير بيئة `SECRET_KEY`) — لا
  تتركه بالقيمة الافتراضية في الإنتاج.
- **غيّر كلمة مرور الأدمن الافتراضية** فور أول تشغيل.
- شغّل التطبيق دائماً عبر `gunicorn` (وليس `python app.py` المباشر) في
  الإنتاج، مع `debug=False` (وهو معطّل بالفعل عند التشغيل عبر gunicorn).
- فعّل HTTPS على الاستضافة لحماية بيانات تسجيل الدخول أثناء النقل.

## 4. ملاحظة حول واجهة حاسبة التعرفة

واجهة `user_dashboard.html` هي نفسها واجهتك الأصلية (حاسبة التعرفة + جدول
التعرفة الجمركية) دون أي تعديل في المنطق أو الحسابات — تم فقط:
- حذف شاشة الدخول القديمة القائمة على كلمة مرور ثابتة في الكود (`1100`).
- إضافة بانر علوي يعرض اسم المستخدم وعدد الأيام المتبقية من الاشتراك.
- ربط زر "خروج" بتسجيل الخروج الفعلي من السيرفر (`/logout`) بدل `location.reload()`.
